# Android-клиент кредитного калькулятора

Мобильный клиент общего проекта `credit-calculator`. Использует тот же Spring Boot API, пользователей Keycloak и заявки, что и веб-интерфейс. Открывайте каталог `android/` как отдельный проект в Android Studio: серверная Gradle-сборка находится в `backend/` и собирается независимо.

## Возможности

- Локальный предварительный расчёт аннуитетных и дифференцированных платежей с графиком.
- Регистрация, вход, восстановление сессии, обновление токенов и профиль.
- Создание заявки, отправка данных на скоринг, просмотр результатов и предложений.
- Выбор предложения, типа платежей и зарплатного счёта.
- Запрос PDF-договора, ожидание асинхронной генерации, скачивание документа.
- Учебное подтверждение подписания через API. Статус хранится на сервере; электронной подписи и реальной выдачи кредита нет.

Предварительный расчёт работает без сервера. Для личного кабинета нужен запущенный бэкенд. Условия договора определяются сервером и выбранным предложением; локальный расчёт носит справочный характер.

## Стек и структура

Kotlin, Jetpack Compose, Material 3, Navigation Compose, Retrofit, OkHttp, Kotlinx Serialization, Coroutines/Flow и Preferences DataStore.

| Каталог | Назначение |
| --- | --- |
| `core/network` | HTTP-клиенты, обработка ошибок, Bearer-токен и повтор запроса после refresh |
| `core/session` | Хранение токенов и управление состоянием сессии |
| `data/model`, `data/remote`, `data/repository` | DTO, Retrofit API и операции с сервером |
| `feature/auth` | Вход, регистрация и профиль |
| `feature/calculator` | Предварительный расчёт и график |
| `feature/applications` | Создание, список и детали заявки |
| `feature/contract` | Документы и подтверждение подписания |
| `feature/navigation`, `core/ui`, `ui/theme` | Навигация, общие компоненты и оформление |
| `artwork` | Исходный SVG значка; ресурсы Android находятся в `app/src/main/res` |

Используется MVVM и ручное внедрение зависимостей через `AppContainer`. Контейнер принадлежит `Application`, поэтому не создаётся заново при повороте экрана. UI наблюдает `StateFlow` с учётом жизненного цикла.

## Запуск

Нужны Android Studio с поддержкой AGP 8.13.2, JDK 17, Android SDK Platform 36 и Build Tools 35.0.0. Минимальная версия устройства — Android 8.0 (API 26). Используйте Gradle Wrapper из этого каталога.

1. Запустите инфраструктуру и четыре сервиса по [основному README](../README.md#локальный-запуск). Gateway должен отвечать на порту 8080.
2. Откройте `android/` в Android Studio и дождитесь Gradle Sync.
3. Запустите конфигурацию `app` на эмуляторе или телефоне.

Для Android Emulator адрес по умолчанию — `http://10.0.2.2:8080/`: это доступ к серверу на компьютере разработчика. `localhost` внутри эмулятора относится к самому Android.

Другой адрес задаётся без редактирования исходников:

```bash
./gradlew :app:assembleDebug -PapiBaseUrl=http://192.168.1.10:8080/
```

Для телефона по USB можно выполнить:

```bash
adb reverse tcp:8080 tcp:8080
./gradlew :app:assembleDebug -PapiBaseUrl=http://127.0.0.1:8080/
```

После установки именно этой сборки приложение обращается к gateway через USB. По Wi-Fi телефон и компьютер должны находиться в одной сети, а порт 8080 должен быть доступен телефону. Адрес всегда должен заканчиваться `/`. В Android Studio можно сохранить `apiBaseUrl` в локальном `~/.gradle/gradle.properties` и пересобрать приложение.

HTTP разрешён только в debug-варианте для локальной разработки. Для release нужен HTTPS-адрес через `-PapiBaseUrl=https://.../` и собственная настройка подписи; ключи и пароли подписи в Git не сохраняются.

## Проверки

Из каталога `android/`:

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

В Windows используйте `gradlew.bat`. JVM-тесты проверяют JSON-контракт подписания, ошибки API, отмену корутин, обновление токенов при конкурентных запросах и выходе, а также расчёты и округление графика. Эти тесты используют локальный HTTP-сервер и не требуют запущенных Keycloak или Kafka.

Сквозная ручная проверка с сервером:

1. Откройте калькулятор без входа и проверьте оба типа платежей.
2. Зарегистрируйтесь или войдите существующим пользователем; проверьте профиль и восстановление сессии после закрытия приложения.
3. Создайте заявку с допустимыми данными, просмотрите скоринг и выберите предложение.
4. Запросите документы и дождитесь `DOCUMENTS_READY`. Если генерация не завершилась за период опроса, обновите экран позже.
5. Скачайте PDF и выполните учебное подтверждение подписания. После обновления страницы в веб-клиенте состояние также должно быть `CONTRACT_SIGNED`.
6. Выйдите из аккаунта, включая сценарий временно недоступного сервера.

На Android 10+ файл сохраняется в `Downloads/CreditCalculatorMobile`; на Android 8–9 — в каталоге загрузок приложения. Разрешение на полный доступ к хранилищу не требуется.

## Сессия и ограничения

Одновременные обновления токена сериализуются; временная ошибка refresh не стирает сохранённые токены. Выход очищает локальную сессию до сетевого запроса. Ответ refresh, пришедший после выхода, не может вернуть старую сессию. Debug-логи не содержат тела запросов с паролями и токенами.

Preferences DataStore хранит токены в приватном каталоге приложения без дополнительного шифрования. Их резервное копирование и перенос исключены XML-правилами. Для дальнейшего развития нужны шифрование с Android Keystore, Authorization Code + PKCE, тесты UI на устройстве и сквозная проверка всей инфраструктуры.

## Разработка и Git

Клиент первоначально загружен в ветку `android`, затем проверен и включён в общий проект в каталоге `android/`. Новые задачи следует выполнять в `feature/android-*` от `develop`, проверять сборкой и тестами и объединять через pull request в `develop`; готовую версию переносить в `main`.

В Git входят исходники, ресурсы, настройки сборки и Gradle Wrapper, включая `gradle-wrapper.jar`. Каталоги `.idea`, `.gradle`, `build`, файл `local.properties`, APK/AAB и ключи подписи исключены. `local.properties` создаётся Android Studio на конкретном компьютере.
